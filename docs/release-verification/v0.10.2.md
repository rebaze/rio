## Recovery of the existing tag

The first build attempt stopped on November 14 at 18:14:41 UTC when Apple rejected the first
notarization submission with `403 FORBIDDEN.REQUIRED_AGREEMENTS_MISSING_OR_EXPIRED`. It had not
created a GitHub release or draft. After the Account Holder reported accepting the agreement,
attempt 2 still received the same response at 20:06:32 UTC, again before draft creation.

A direct, read-only `notarytool history` check with the release API key initially reproduced the
403, then succeeded after a short wait. This is consistent with the account change propagating.
Only the failed jobs of the existing run were retried. The original tagged-source CI and CodeQL
successes were retained. No tag was deleted or moved, and no existing release or assets were
replaced. The blocker and recovery are recorded in
[#228](https://github.com/rebaze/rio/issues/228).

Attempt 3's build finished at 20:14:20 UTC. The publication job made the checked draft public at
20:14:34, the Homebrew update finished at 20:14:48, and native verification finished at 20:17:35.

## Published downloads

Native execution passed on Linux amd64, macOS arm64 and Windows amd64, each running the client
demo. On macOS the verifier executed the quarantined download only after Gatekeeper reported
`Notarized Developer ID` for rebaze GmbH (32Z95ATB2T). The Homebrew installation passed the same
assessment and reported version 0.10.2, the full release commit and build date.

The other three architecture archives were authenticated and checksum-verified, but were not
executed by those runners. All six extracted binaries were separately scanned with the pinned
govulncheck; all were clean and all contained Go 1.27.4.

## Scope

This patch rebuilds Rio with Go 1.27.4 to address GO-2026-6859 / CVE-2026-97054 and makes CI and
release builds track patch updates within the reviewed Go minor line. The source fix and
post-mortem are [#224](https://github.com/rebaze/rio/issues/224) and
[#226](https://github.com/rebaze/rio/issues/226). CLI behavior and manifest, receipt and delivery
formats are unchanged.

Notarization is Apple's automated malware scan, not a review of Rio's behavior. Windows binaries
are not Authenticode-signed. Synthetic receiver acknowledgments do not establish ingestion or
long-term retention. The vulnerability scan records the advisory database available at its stated
time; it is not a guarantee against future findings.
