# Rio v0.10.0 release verification

[Rio v0.10.0](https://github.com/rebaze/rio/releases/tag/v0.10.0) was published on 2026-11-10
from `53af628e3144422dd4003a52309439ff75262512`, the merge commit of
[PR #215](https://github.com/rebaze/rio/pull/215). That commit differs from the validated candidate
`7b1f6bc272d290fcf1e40333a228ff7c6ae60b9e` (the merge commit of
[PR #214](https://github.com/rebaze/rio/pull/214)) only in `docs/releases/v0.10.0.md`. All ten
assets were downloaded and verified on three native runners. The release body matches the exact
[authored notes](../releases/v0.10.0.md) byte for byte, and each summary records `notesSource: authored`.

| [CodeQL](https://github.com/rebaze/rio/actions/runs/42704731847) and [Installer tests](https://github.com/rebaze/rio/actions/runs/42704731954) | Passed at the candidate `7b1f6bc` | Workflow execution; candidate builds on Linux, macOS and Windows |

The `build` job finished at 06:24:34 UTC and `publish` made the draft public at 06:24:50. Nothing
needed a re-run.

Native execution passed on Linux amd64, macOS arm64 and Windows amd64, each running the client
demo. On macOS the verifier ran the downloaded binary under a quarantine attribute only after
Gatekeeper reported `Notarized Developer ID` for rebaze GmbH (32Z95ATB2T). The Homebrew job
required the same assessment of the installed binary, which reported version 0.10.0, the full
source commit and the build date. The other three architecture archives were authenticated and
checksum-verified, but were not executed by these runners.

The generated verification summaries are kept here, so the hashes remain inspectable after the
temporary Actions artifacts expire:

- [Linux amd64](v0.10.0/linux.json)
- [macOS arm64](v0.10.0/macos.json), including the Gatekeeper assessment
- [Windows amd64](v0.10.0/windows.json)
- [Homebrew version output](v0.10.0/homebrew-version.txt) and [Gatekeeper assessment](v0.10.0/homebrew-gatekeeper.txt)

All three summaries agree on the ten asset hashes and the authored-notes hash.

## Scope

The behaviour changes since v0.9.0 are in the [release notes](../releases/v0.10.0.md):
- subject links, issue tracker, release notes and advisories in enrichment (#202);
- Dependency-Track project tags, parent and latest version, with the read-back in the receipt
  (#203, #213);
- the integration harness and CI on Dependency-Track 5.2.1 (#212).

Rio was built with Go 1.27.3.

Notarization is Apple's automated malware scan of the submitted binary; it is not a review of Rio's
behaviour. Windows binaries are not Authenticode-signed. Synthetic receiver acknowledgments do not
establish ingestion or long-term retention, and the 5.2.1 evidence covers that version only.
