## Security scope and deferred work

Rio and the release tools were built with Go 1.27.2. The release-tool audit retains
GO-2026-5932 and GO-2026-6225 as narrowly reviewed unused-feature dispositions;
these are not blanket declarations that the tools are vulnerability-free.
Syft's OpenPGP finding is module-only. The
[versioned recipe](https://github.com/rebaze/rio/blob/v0.7.2/tools/release-toolchain/README.md)
and manifest define the permitted invocation scope and fail-closed checks.

The intentionally vulnerable Juice Shop dependency-lock work remains deferred
under [#119](https://github.com/rebaze/rio/issues/119), as agreed. Apple notarization
[#17](https://github.com/rebaze/rio/issues/17), Artifactory validation
[#88](https://github.com/rebaze/rio/issues/88) and badge registration
[#37](https://github.com/rebaze/rio/issues/37) remain separate follow-ups. Synthetic
receiver acknowledgments do not establish ingestion or long-term retention.

## v0.7.1 recovery

The immutable v0.7.1 tag points to `2cdc4f1975f90bb354d4329244aa8009401adcdb`.
Its [release run](https://github.com/rebaze/rio/actions/runs/38295916745) failed at
startup because reusable CodeQL requested `read-all` beyond the caller's grant.
No release jobs ran and no v0.7.1 release was published. PR #137 narrowed the
permissions and added preflight validation. The recovery used a new patch tag;
v0.7.1 was neither moved nor deleted.

This evidence completes the maintenance release acceptance in
[#122](https://github.com/rebaze/rio/issues/122) and the security/CI batch
[#123](https://github.com/rebaze/rio/issues/123).
