# Rio v0.8.2 release verification

v0.8.2 is the first release that waited for a release gate before publication. The release job
stood in the `release` environment from 12:05 until the Clear to Ship App, a custom deployment
protection rule, approved it at 12:15 UTC; the gate's check on the release commit reads
"[Gate 4 is clear and shipped](https://github.com/rebaze/rio/runs/120397246763)". Among the
gate's checkpoints are the source SBOM and Rio's receipt that release preflight attested for
this commit, and a person's decisions on the release notes and the publication.

[Rio v0.8.2](https://github.com/rebaze/rio/releases/tag/v0.8.2) was published on
2026-10-23 from `25a9d490be8941eccc2e91f39d719f9d6f1780bf`, the merge commit of
[PR #178](https://github.com/rebaze/rio/pull/178). All ten assets were downloaded
and verified on three native runners. The release body matches the exact
[authored notes](../releases/v0.8.2.md).

| Evidence | Result | Scope |
|---|---|---|
| [Integrated CI](https://github.com/rebaze/rio/actions/runs/39947632314) | Passed at the release commit | Go tests, vulnerability scan, installed-binary demos and real OCI/Dependency-Track receivers |
| [CodeQL](https://github.com/rebaze/rio/actions/runs/39947632322) and [Scorecard](https://github.com/rebaze/rio/actions/runs/39947632337) | Passed at the release commit | Workflow execution; not a claim that all possible security risks are absent |
| [Release preflight](https://github.com/rebaze/rio/actions/runs/39947773862) | Passed at the release commit | Full CI and CodeQL, the candidate's source SBOM checked by its own Rio build, both attested to the commit |
| [Installer tests](https://github.com/rebaze/rio/actions/runs/39947632317) | Passed at the release commit | Candidate builds on Linux, macOS and Windows: version and commit, client-record demo, offline installer |
| [Release pipeline](https://github.com/rebaze/rio/actions/runs/39949929593) | Passed after the gate approved | Full tagged-source gates, Developer ID signing and Apple notarization of both darwin binaries, signed checksums, provenance and source-SBOM attestations, exact staged/uploaded-byte verification, publication and Homebrew update |
| [Published-release verification](https://github.com/rebaze/rio/actions/runs/40103096297) | All four jobs passed | Complete downloaded asset set, checksums, Sigstore identity, exact source-commit attestations, authored notes, native demos, Gatekeeper assessment and fresh Homebrew installation |

The published-release verification ran on 2026-10-24, a day after publication, because it was
still started by hand and had been missed. From the next release on, the release workflow runs it
after the Homebrew update ([#179](https://github.com/rebaze/rio/issues/179)).

Native execution passed on Linux amd64, macOS arm64 and Windows amd64. On macOS the
verifier marked the downloaded binary with a real `0381` quarantine attribute, required
Gatekeeper to report `Notarized Developer ID` for rebaze GmbH (32Z95ATB2T), and only then
ran it. The Homebrew job confirmed that the installed binary still carried Homebrew's
quarantine mark, then required the same assessment and reported the same version, full
source commit and build date. The other three architecture archives were authenticated and
checksum-verified, but were not natively executed by these runners.

The generated verification summaries are retained here so the hashes remain
inspectable after temporary Actions artifacts expire:

- [Linux amd64](v0.8.2/linux.json)
- [macOS arm64](v0.8.2/macos.json), including the Gatekeeper assessment
- [Windows amd64](v0.8.2/windows.json)
- [Homebrew version output](v0.8.2/homebrew-version.txt) and [Gatekeeper assessment](v0.8.2/homebrew-gatekeeper.txt)

All three summaries agree on the ten asset hashes and authored-note hash.

## Scope

The opt-in `gate.subject.require: [securityContact]` requirement and the actionable gate failures
([#45](https://github.com/rebaze/rio/issues/45)) are the only behavior change since v0.8.1; the
receipt gains the effective subject requirements and `checks.failed`. Commands and flags are
unchanged. Rio was built with Go 1.27.3, which fixes GO-2026-6809.

The gate's approval names the release commit, not the published bytes; binding it to the asset
digests is [#165](https://github.com/rebaze/rio/issues/165). Notarization is Apple's automated
malware scan of the submitted binary; it is not a review of Rio's behavior. Windows binaries are
not Authenticode-signed. Synthetic receiver acknowledgments do not establish ingestion or
long-term retention.
