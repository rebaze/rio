# Rio v0.9.0 release verification

v0.9.0 is the first release staged as a draft and published only from the gated `publish` job
([#165](https://github.com/rebaze/rio/issues/165)), and the first whose own SBOM declares its
inventory complete ([#190](https://github.com/rebaze/rio/issues/190)). The build job staged the
draft and uploaded its files as run artifacts by 18:12:50 UTC. The Clear to Ship App, the custom
deployment protection rule of the `release` environment, checked them and recorded gate 6 as
shipped at 18:12:58. The `publish` job made the draft public at 18:13:12. The gate's check on the
release commit reads "[Shipped](https://github.com/rebaze/rio/runs/121742442867)".

[Rio v0.9.0](https://github.com/rebaze/rio/releases/tag/v0.9.0) was published on 2026-10-26
from `4fa2eb33cd533267e11d1ea7878800924fc9070a`, the merge commit of
[PR #191](https://github.com/rebaze/rio/pull/191). All ten assets were downloaded and verified on
three native runners. The release body matches the exact [authored notes](../releases/v0.9.0.md).

| Evidence | Result | Scope |
|---|---|---|
| [Integrated CI](https://github.com/rebaze/rio/actions/runs/40368320024) | Passed at the release commit | Go tests, vulnerability scans of Rio and its pinned tools, the source-SBOM check, installed-binary demos and real OCI/Dependency-Track receivers |
| [CodeQL](https://github.com/rebaze/rio/actions/runs/40368320255) and [Scorecard](https://github.com/rebaze/rio/actions/runs/40368320034) | Passed at the release commit | Workflow execution; not a claim that all possible security risks are absent |
| [Release preflight](https://github.com/rebaze/rio/actions/runs/40370211709) | Passed at the release commit | Full CI and CodeQL; Rio's own SBOM checked against `bsi-tr-03183-2@2.1.0` by the candidate's Rio; the SBOM and the receipt attested to the commit |
| [Installer tests](https://github.com/rebaze/rio/actions/runs/40368320070) | Passed at the release commit | Candidate builds on Linux, macOS and Windows: version and commit, client-record demo, offline installer |
| [Release pipeline](https://github.com/rebaze/rio/actions/runs/40373616694) | Passed on its second attempt | Full tagged-source gates, Developer ID signing and Apple notarization of both darwin binaries, signed checksums, provenance and source-SBOM attestations, a draft checked against the run artifacts, publication, the Homebrew update and published-release verification |

The first attempt of the release pipeline stopped before building anything. Its CI pass could not
download GoReleaser (HTTP 504 from GitHub three times). No draft existed, so only the failed jobs
were run again, and the second attempt passed.

Published-release verification now runs inside the release workflow, after the Homebrew update
([#179](https://github.com/rebaze/rio/issues/179)), not by hand a day later as for v0.8.2.

Native execution passed on Linux amd64, macOS arm64 and Windows amd64. On macOS the verifier
marked the downloaded binary with a real `0381` quarantine attribute. It required Gatekeeper to
report `Notarized Developer ID` for rebaze GmbH (32Z95ATB2T), and only then ran the binary. The
Homebrew job required the same assessment of the installed binary. It reported the same version,
the full source commit and the build date. The other three architecture archives were
authenticated and checksum-verified, but were not natively executed by these runners.

The generated verification summaries are kept here, so the hashes remain inspectable after the
temporary Actions artifacts expire:

- [Linux amd64](v0.9.0/linux.json)
- [macOS arm64](v0.9.0/macos.json), including the Gatekeeper assessment
- [Windows amd64](v0.9.0/windows.json)
- [Homebrew version output](v0.9.0/homebrew-version.txt) and [Gatekeeper assessment](v0.9.0/homebrew-gatekeeper.txt)

All three summaries agree on the ten asset hashes and the authored-note hash.

## Rio's own SBOM

The attestations of release preflight for the release commit, read back from GitHub:

- **The receipt** records Rio 0.9.0's gate in mode `fail`. It passed against `bsi-tr-03183-2@2.1.0`
  with no findings, 14 components evaluated, and name, version and purl still required.
- **The source SBOM** has subject `rio 0.9.0`, 14 components (13 linked Go modules and the
  standard library), a dependency entry for each, and a root composition `complete`.
- **The match:** re-indenting the attested predicate with two spaces and a trailing newline gives
  the file Rio wrote, byte for byte. Its SHA-256 equals the receipt's `output.sha256`
  ([cleartoship#114](https://github.com/rebaze/cleartoship/issues/114)).

The release made the SBOM again, the same way, for the published asset
`rio-v0.9.0-source.cdx.json`. Its content is the same, but its bytes are not: the timestamp and
the serial number differ. Shipping the exact bytes the gate judged is
[#194](https://github.com/rebaze/rio/issues/194). Clear to Ship's inventory check gives both
copies `complete`.

## Scope

The behaviour changes since v0.8.2 are in the [release notes](../releases/v0.9.0.md):
- the requirement profile `gate.profile: bsi-tr-03183-2@2.1.0` and TR file components (#170);
- shipped files in the build context (#171);
- normalizing Rio's own output (#181);
- the draft-then-publish release (#165);
- Rio's own complete SBOM (#190).

Without a profile, the only behaviour changes are these:
- `enrichment.dataLicense` refuses SPDX exception identifiers;
- a dependency reference to a component nested under the subject is no longer dangling.

Rio was built with Go 1.27.3.

A pass of the profile shows that the required fields are present and well formed. It does not
establish that they are true, and the `complete` claim covers the Go modules linked into the
binaries, not the toolchain or the other files in the archives. Notarization is Apple's automated
malware scan of the submitted binary; it is not a review of Rio's behaviour. Windows binaries are
not Authenticode-signed. Synthetic receiver acknowledgments do not establish ingestion or
long-term retention.
