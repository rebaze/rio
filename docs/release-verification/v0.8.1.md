# Rio v0.8.1 release verification

v0.8.1 is the first release whose macOS binaries are signed with rebaze's Developer ID and
notarized by Apple. This is what Gatekeeper reported for the Homebrew installation on a fresh
GitHub macOS runner, with Homebrew's quarantine mark still on the binary:

```text
/opt/homebrew/Caskroom/rio/0.8.1/rio: accepted
source=Notarized Developer ID
origin=Developer ID Application: rebaze GmbH (32Z95ATB2T)
```

[Rio v0.8.1](https://github.com/rebaze/rio/releases/tag/v0.8.1) was published on
2026-10-15 from `34eb468554e01af13c403150bcaf492972ee78cc`, the merge commit of
[PR #148](https://github.com/rebaze/rio/pull/148). All ten assets were downloaded
and verified on three native runners. The release body matches the exact
[authored notes](../releases/v0.8.1.md).

| Evidence | Result | Scope |
|---|---|---|
| [Integrated CI](https://github.com/rebaze/rio/actions/runs/38775204794) | Passed at the release commit | Go tests, vulnerability scan, installed-binary demos and real OCI/Dependency-Track receivers |
| [CodeQL](https://github.com/rebaze/rio/actions/runs/38775205091) and [Scorecard](https://github.com/rebaze/rio/actions/runs/38775204781) | Passed at the release commit | Workflow execution; not a claim that all possible security risks are absent |
| [Release pipeline](https://github.com/rebaze/rio/actions/runs/38775228060) | Passed | Full tagged-source gates, Developer ID signing and Apple notarization of both darwin binaries, signed checksums, provenance and source-SBOM attestations, exact staged/uploaded-byte verification, publication and Homebrew update |
| [Published-release verification](https://github.com/rebaze/rio/actions/runs/38776486008) | All four jobs passed | Complete downloaded asset set, checksums, Sigstore identity, exact source-commit attestations, authored notes, native demos, Gatekeeper assessment and fresh Homebrew installation |

Native execution passed on Linux amd64, macOS arm64 and Windows amd64. On macOS the
verifier marked the downloaded binary with a real `0381` quarantine attribute, required
Gatekeeper to report `Notarized Developer ID` for rebaze GmbH (32Z95ATB2T), checked
`codesign --verify --strict`, and only then ran it. The Homebrew job confirmed that the
installed binary still carried Homebrew's quarantine mark, then required the same
assessment and reported the same version, full source commit and build date. The other
three architecture archives were authenticated and checksum-verified, but were not
natively executed by these runners; the darwin amd64 binary was signed and notarized in
the same release step as darwin arm64.

The generated verification summaries are retained here so the hashes remain
inspectable after temporary Actions artifacts expire:

- [Linux amd64](v0.8.1/linux.json)
- [macOS arm64](v0.8.1/macos.json), including the Gatekeeper assessment
- [Windows amd64](v0.8.1/windows.json)
- [Homebrew version output](v0.8.1/homebrew-version.txt) and [Gatekeeper assessment](v0.8.1/homebrew-gatekeeper.txt)

All three summaries agree on the ten asset hashes and authored-note hash.

## Scope

No Go source file changed since v0.8.0; the only module change is `doublestar` 4.10.3.
Commands, flags, manifest and receipt format are unchanged. Rio was built with Go 1.27.2. Cosign, Syft
and GoReleaser came from their official actions pinned by commit, so there is no rebuilt
release-tool audit for this release.

Notarization is Apple's automated malware scan of the submitted binary; it is not a review
of Rio's behavior. Windows binaries are not Authenticode-signed. Artifactory validation
[#88](https://github.com/rebaze/rio/issues/88) and badge registration
[#37](https://github.com/rebaze/rio/issues/37) remain separate follow-ups. Synthetic
receiver acknowledgments do not establish ingestion or long-term retention.
