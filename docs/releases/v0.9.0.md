# Rio v0.9.0

**Rio can check an SBOM against BSI TR-03183-2 2.1.0, and a build can declare the files it ships.**

Set `gate.profile: bsi-tr-03183-2@2.1.0` and the gate checks each SBOM against that requirement set
before anything is delivered. A generator's SBOM usually fails it, and Rio says which field is
missing and what to do about it. This is the output of the handoff demo,
[`tools/demo-handoff-checks`](https://github.com/rebaze/rio/blob/v0.9.0/tools/demo-handoff-checks),
trimmed to the failing scenario and its repair. The data is synthetic (the artifact `cart-api` and
its digests are made up); the output comes from a binary built from this release's source.

```text

   checks.gate: fail
   checks.failed: ['sbom.creator', 'subject.creator', 'subject.filename', 'subject.deployableHash', 'subject.executable', 'subject.archive', 'subject.structured']
   checks.profile: {"guideline": "BSI TR-03183-2", "guidelineVersion": "2.1.0", "name": "bsi-tr-03183-2@2.1.0"}

     subject.creator (BSI TR-03183-2 2.1.0 §5.2.2): the SBOM subject has no creator (manufacturer). Set enrichment.subject.manufacturer in rio.yaml, or have the SBOM generator emit one.

== bsi-profile-repaired -> exit 0 - delivered
   checks.gate: pass
   checks.profile: {"guideline": "BSI TR-03183-2", "guidelineVersion": "2.1.0", "name": "bsi-tr-03183-2@2.1.0"}
```

The repair is reviewed enrichment in `rio.yaml` plus a build context file that declares a logical
subject and two shipped files. A pass shows that the fields are present and well formed, nothing
more: Rio never hashes a file, opens an archive or judges whether a value is true.

## What changed

- **Requirement profile** ([#170](https://github.com/rebaze/rio/issues/170)). `gate.profile`
  accepts `bsi-tr-03183-2@2.1.0`, the only known profile; the name pins the guideline version.
  The failures are listed in the receipt (`checks.failed`, `checks.profile`,
  `checks.profileLevels`), on stderr with the next step, and in the HTML report. `rio plan`
  shows the profile, and `--json` carries it as `gate.profile`. The profile checks presence and
  form only, in `rio` and in `rio normalize`. See
  [Requirement profiles](https://github.com/rebaze/rio/blob/v0.9.0/docs/manifest.md#requirement-profiles).
- **TR file components** ([#170](https://github.com/rebaze/rio/issues/170)). Rio turns build
  context `distributions` that carry `sha512` and the executable, archive and structured
  properties into the file components the TR asks for, nested under the subject. The context also
  takes a `level` to declare a subject logical or assembled. `index.json` component membership
  is unchanged. `tools/rio-context.py` gains `--sha512-checksums` and `--file-properties
  PATTERN=FLAGS` (the first requires the second) and `--level`.
- **Shipped files** ([#171](https://github.com/rebaze/rio/issues/171)). A build declares the files
  it ships under `distributions` in the build context file. Rio writes them into the SBOM subject
  as `distribution` references and lists them in the receipt as `artifacts[].distributions`,
  as producer assertions. `tools/rio-context.py --checksums` turns a sha256sum or GoReleaser
  checksums file into `distributions` entries. `gate.subject.require: [digest]` blocks delivery without them.
- **Rio can normalize its own output again** ([#181](https://github.com/rebaze/rio/issues/181)).
  It records itself in `metadata.tools` once per version.
- **A safer release path** ([#165](https://github.com/rebaze/rio/issues/165)). The release is
  staged as a draft and published only from the gated `publish` job, which checks the published
  assets against the run artifacts by name and digest.
- **Nested references are known** ([#170](https://github.com/rebaze/rio/issues/170)). The
  integrity check now knows the bom-refs of components nested under the subject, so a dependency
  reference to one is no longer a dangling reference and `graphFindings` can drop against
  v0.9.0-rc1, with or without a profile.

## Compatibility

Rio v0.8.2 and older cannot read receipts or SBOM context records that carry `distributions`.
Rio v0.9.0-rc1 and older cannot read the TR distribution fields, a context `level`, receipts that
carry `checks.profile` or `profileLevels`, or the new failure IDs; rc1 refuses a context record
with `level` (`effective: unknown key "level"`). Commands,
flags and the rest of the manifest are unchanged, and a manifest without `gate.profile` behaves
as before.
