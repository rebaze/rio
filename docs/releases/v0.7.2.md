## Security maintenance

- Raise the required Go compiler from 1.27.0 to 1.27.2 in Rio and the security-tool module,
  addressing the ten reachable standard-library advisories detected by CI on October 12.
- Update `golang.org/x/text` from 0.39.0 to 0.41.0 for GO-2026-6629. The affected package was
  not imported by Rio, but the vulnerable version is removed from its module inventory.
- Keep scanner exceptions limited to the Commons Lang metadata in the captured synthetic
  example directories. Original receipt-bound bytes remain unchanged; real dependencies and
  the same advisory outside those directories remain scanned.

Existing downloaded static binaries are unchanged. Install this release to receive its rebuilt binary.

## Pipeline reliability

This is the published maintenance update after v0.7.0. The v0.7.1 tag remains
reserved: GitHub rejected its workflow before any release jobs or publication.
The reusable CodeQL workflow now requests only the permissions granted by its
release caller. A non-publishing release preflight exercises both reusable gates
before another tag is created.

Release publication now depends on complete CI and CodeQL execution for the tagged source,
followed by the existing verification of exact staged assets. Manual and scheduled CI run all
check groups. An aggregate result covers native Linux/macOS/Windows tests and real OCI and
Dependency-Track receivers. The security-update bot also requires that aggregate before merging.
CodeQL completion is not a new policy that treats every reported finding as a release refusal.

The hard-kill recovery test keeps its child alive until termination instead of racing Go's
runtime deadlock detection. Repeated tests preserve no-replay and crash-lock assertions.
Syft and GoReleaser versions are explicit; weekly version checks raise reviewable update work.
They do not automatically install, merge or publish updates.

## Verification limits

The Rio source/module vulnerability scan is distinct from its third-party release tools.
Cosign, Syft and GoReleaser are now rebuilt from verified upstream modules with Go 1.27.2
and explicit patched dependency locks. Their symbols are retained for auditing. Unexpected
advisories fail the build; two legacy-feature advisories remain visible with narrowly reviewed
command-specific dispositions. Syft's OpenPGP finding is module-only, with no affected package
imports in the rebuilt tool.

[Build recipe and scope](https://github.com/rebaze/rio/blob/v0.7.2/tools/release-toolchain/README.md) · [Original upstream-binary audit](https://github.com/rebaze/rio/blob/v0.7.2/tools/security/pipeline-audit-2026-10-12.json)

The original stripped Syft/GoReleaser scans used module-level fallback, so their counts were
not proof that every listed vulnerable function was present. These dispositions apply only
to Rio's reviewed commands, not arbitrary use of the tools. Artifactory validation and Apple
notarization remain separate follow-ups.
