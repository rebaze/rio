# Rio v0.9.1-rc1

**A pre-release that rehearses releasing Rio without an approval gate. Install a stable release for real use; the Homebrew cask is not updated.**

It contains what is on `main` for v0.9.1 so far. For Rio's users that is one dependency update in
OCI delivery; the rest is how Rio itself is released.

One `rio --json` run of the OCI walkthrough,
[`tools/demo-oci`](https://github.com/rebaze/rio/blob/v0.9.1-rc1/tools/demo-oci), checks an SBOM
and delivers it to an OCI registry and to Dependency-Track. This is its run receipt, written by a
binary built from this pre-release's commit, with only some fields kept: the receipt also records
the SHA-256 and size of the input and output SBOMs, each submitted body's media type, and the
digest and size of the OCI config and manifest. The data is synthetic, and both receivers are a local stub, not a real registry or Dependency-Track.

```json
{
  "artifacts": [
    {
      "id": "application",
      "state": "completed",
      "checks": { "gate": "pass", "findings": 0 }
    }
  ],
  "deliveries": [
    {
      "target": "registry",
      "project": {
        "repository": "demo/application",
        "tag": "rio-sbom-sha256-70b0a277f8558a3825c2dd3d8a75e2b5086b0ec5934242dce6228425bb997241"
      },
      "state": "accepted",
      "submitted": [{ "role": "oci-config" }, { "role": "sbom" }, { "role": "oci-manifest" }]
    },
    {
      "target": "security",

}
```

## What changed

- **OCI delivery uses oras-go 2.7.0**, up from 2.6.4
  ([#192](https://github.com/rebaze/rio/pull/192)). The OCI walkthrough and CI's delivery tests
  against a real OCI distribution registry pass unchanged.

## Release process

- **Pushing a tag is enough to release** ([#199](https://github.com/rebaze/rio/issues/199)). No
  external approval holds publication any more: `publish` runs right after `build`. Only
  repository admins can push a release tag.
- **Release notes in the source are optional.** When `docs/releases/<tag>.md` exists, its exact
  bytes are still the release body. A tag without one is published with generated notes instead
  of failing.
