# Rio v0.8.2

**Rio can now require a security contact, and a failed gate says what to do next.**

A manifest that sets `gate.subject.require: [securityContact]` fails the gate unless the SBOM's
subject names a security contact: an absolute `http(s)` URL without credentials, or `mailto:` with
one address. A reviewed `enrichment.subject.securityContact` satisfies it; Rio never looks a
contact up. Without the setting, nothing changes.

## What changed

- When the gate fails, `rio` and `rio normalize` explain each failed requirement on stderr with
  the next step, and say whether delivery happened. Before, the root pipeline printed no reason.
- The receipt lists the effective subject requirements and, for a failed gate, `checks.failed`
  with stable requirement IDs and counts; the HTML report shows them. `index.json` records
  `subjectRequirements` only when they are opted in.
- This release was checked before its tag: release preflight attested the source SBOM and Rio's
  own receipt for it to the candidate commit, and the installer tests ran on Linux, macOS and
  Windows with the candidate's build. A release gate can verify both for the exact commit.
- Rio is built with Go 1.27.3, which fixes GO-2026-6809 in `crypto/x509`.
- The latest published release is scanned for vulnerabilities every week.
- [Recovering from a broken release](https://github.com/rebaze/rio/blob/v0.8.2/docs/recovery.md)
  is written down, including restoring the Homebrew cask through a tap pull request.
- The installation instructions follow right after the leading example, and say from which
  release the macOS binaries are notarized.

Rio's commands, flags and manifest are unchanged from v0.8.1, apart from the new opt-in
`securityContact` requirement. The receipt gains the fields above.
